## Verdict

**No fixable gap was found, so this report is the whole result.** Nothing in the scoped diff is a
missing or wrong-role `requireOrgRole`, a fail-open check, a missing signature/secret verification, or
a secret or token in a response or a log — the four classes this dispatch was authorized to repair. No
source file was changed by this pass.

Five findings are recorded below. Each is either a *consistency* gap whose repair changes behaviour
for non-browser callers, or an accepted product trade-off the code already documents. None is fixed
here; each names its remedy.

Positive results worth stating, because they are what the dispatch was sent to doubt:

- **Credential custody is correct.** `ProviderCredential.credentialRef` holds only
  `encryptSecret()` ciphertext; the wire type `ProviderConnectionRow` has no field for the key or the
  ciphertext; `getProviderSecret` is the only reader that decrypts and only the sync route calls it;
  both write doors refuse when `ENCRYPTION_KEY` is unset (409 at the route, `throw` in the store); the
  undecryptable-key log records `{ orgSlug, provider }` and never the value; and the org erase drains
  the table (`src/lib/db/retention.ts:2092`, surfaced as `providerCredentialsDeleted`).
- **The capability tokens are sound.** `/api/live/pulse` takes the org **only** from the token, via
  the same `resolveLiveShare` the kiosk page uses: HMAC with a domain prefix (timing-safe), an `aud`
  check, expiry enforced on every read, per-link `jti` revocation and minter owner-binding — and both
  stateful checks fail closed on a lookup error. A `wall` link is refused for the theater pulse. The
  mentor share is owner-self with no id in the path, so no request can address another person's row.
- **No SSRF in the probe path.** `resolveLocalEndpoint` reads the base URL from the server
  environment, never from the request; the browser deliberately sends no URL. The caller-supplied
  `model` reaches only a JSON body and operator-facing prose, never a URL path. The PDF logo fetch
  (`resolveSafeLogoDataUri`) resolves the host and rejects any private/internal address, refuses
  redirects, caps bytes and hands @react-pdf a `data:` URI.
- **Every webhook and cron door verifies.** `verifyWebhook` returns false with no secret;
  `/api/billing/webhook` exports a 503 handler when `POLAR_WEBHOOK_SECRET` is unset;
  `requireCronAuth` 503s on an unset `CRON_SECRET` and compares in constant time;
  `seedRequestAuthorized` refuses the secret-less path in production and compares in constant time.
- **Every `[id]` route in scope resolves the org from the row** and gates that
  (`rowGate`/`getSegmentOrgSlug`/`getLoopPlanOrgSlug`/`getLoopDirectionOrgSlug`/`resolvePlaybookOrg`/
  `getOrgSkillOrgSlug`), or gates a caller-supplied org and constrains the query by it. No route takes
  a caller-supplied org *beside* a caller-supplied id.
- **Both new client-facing db row types** (`MentorShareRow`, `ProviderConnectionRow`) are declared in
  the `wire-safe-dates` guard's list, and both carry ISO strings.

## Findings

### F1 — `low` — Six new mutating routes omit the same-origin (CSRF) guard their siblings carry

| | |
| --- | --- |
| Severity | low |
| Files | `src/app/api/integrations/openai/sync/route.ts:54`, `src/app/api/org/skills/retire/route.ts:55`, `src/app/api/org/ai-stance/apply-batch/route.ts:30`, `src/app/api/org/segments/[id]/rule/route.ts:49` and `:66`, `src/app/api/org/local/runner/merge/route.ts:33`, `src/app/api/org/local/probe/route.ts:171` |

`requireSameOrigin` is this codebase's CSRF defence, and the pattern is near-universal on mutating
`/api/org/*` POSTs — `requireOrgOwnerPost` bakes it in, and the immediate siblings of four of these
routes call it explicitly (`integrations/openai` PUT/DELETE at `:64`/`:107`, `org/alerts` POST at
`:195`, `org/loop/seen` at `:31`, `org/loop/plans/[id]` at `:45`). The six routes above do not.

**Exploit sketch.** A signed-in owner visits `evil.test`, which auto-submits a form or issues a
`fetch(..., {credentials: "include", mode: "no-cors"})` to
`POST /api/org/skills/retire` with `{org, ids:[…]}`, or to `POST /api/org/local/runner/merge` with
`{org, repo}` — bulk-archiving library rows, or fast-forwarding the operator's base branch onto
`ascent/runner`, with no interaction beyond the page load. For `integrations/openai/sync` the forged
call spends the org's OpenAI Admin-API budget and overwrites a day's usage records.

**Why it is `low` and not higher.** Both live session cookies are `SameSite=Lax` (the Ascent session
cookie is set that way in `src/lib/auth.ts:186`, and `@supabase/ssr` defaults the same), so a
cross-site `POST` carries no credential and the request authenticates as anonymous — which
`requireOrgRole` then refuses. The guard is defence-in-depth against a future cookie-attribute change,
a `GET`-shaped variant, or a same-site-but-different-origin subdomain. `org/local/*` is additionally
self-hosted-only, i.e. a localhost deployment.

**Remedy.** Add `const xo = requireSameOrigin(request); if (xo) return xo;` as the first statement of
each handler. **Not applied here**: it is a behaviour change for non-browser callers (an `openai/sync`
or `runner/merge` driven from a script sends no `Origin` and no `Sec-Fetch-Site`, and would start
getting a 403), which is outside this dispatch's fix authorization and is a product call.

### F2 — `low` — The anonymous scan funnel mails a caller-supplied address

| | |
| --- | --- |
| Severity | low |
| File | `src/app/api/scan/stream/route.ts:137`–`:141` |

```ts
const notifyTo = !body.notify
  ? undefined
  : viewer
    ? (isValidEmail(viewer.email) ? viewer.email : undefined)
    : (isValidEmail(body.email) ? body.email.trim() : undefined);
```

**Exploit sketch.** An unauthenticated caller `POST`s `{ url: "<any public repo>", notify: true,
email: "victim@example.com" }`. On completion Ascent's verified sending domain delivers a scan-report
mail to an address that never asked for it — a branded-spam / low-grade mail-amplification lever. The
signed-in branch is already closed (a viewer can only ever be mailed their own account address, and
the comment records that the old `viewer?.email ?? body.email` fallback was the open relay).

**Why it is `low`.** One mail per completed real scan, behind the shared per-IP and fleet-wide burst
limiter and the rolling monthly free-scan allowance — so the rate is bounded and attributable, and the
content is a fixed report notification, not attacker-authored text.

**Remedy.** Double opt-in for an anonymous recipient (mail a confirm link; send the report only once
confirmed). **Not applied here**: the code already states this as a deliberate trade-off with the
fuller anti-abuse step tracked as a follow-up, and changing it changes the advertised no-signup funnel.

### F3 — `low` — `region` is passed to the AWS SDK unvalidated, so an owner picks the request target

| | |
| --- | --- |
| Severity | low |
| Files | `src/app/api/org/llm-provider/test/route.ts:109`, `src/lib/llm/bedrock.ts:52` (`resolveBedrockRegion`), `src/lib/db/org-llm.ts:167` |

`body.region?.trim()` flows straight into `BedrockRuntimeClient({ region })`, and
`resolveBedrockRegion` applies no grammar. The SDK interpolates the value into its endpoint template
`https://bedrock-runtime.{Region}.amazonaws.com`.

**Exploit sketch.** An org owner on an Enterprise/BYOM plan saves or tests `region: "example.com/"`.
The resolved endpoint becomes `https://bedrock-runtime.example.com/.amazonaws.com`, so the server
issues a SigV4-signed request to a host the caller chose — an outbound-egress probe from inside the
app network. The `bedrock-runtime.` prefix is what keeps this from reaching bare `localhost` or
`169.254.169.254`, and the credentials signed into the request are the owner's own, which is why this
is a target-selection weakness rather than a credential leak.

**Remedy.** Validate against the AWS region grammar — `/^[a-z]{2}(-[a-z]+)+-\d$/` — in
`resolveBedrockRegion`, so both the provider constructor and this test door inherit it. **Not applied
here**: rejecting a previously-accepted stored value is a product behaviour change (an org with a
non-conforming saved region would start seeing a 400), outside this dispatch's fix authorization.

### F4 — `informational` — `/api/org/loop/needs-you` lacks the `PUBLIC_ORG` refusal its siblings carry

| | |
| --- | --- |
| Severity | informational |
| File | `src/app/api/org/loop/needs-you/route.ts:26`–`:30` |

Every other loop read refuses the funnel org explicitly before gating — `loop/pulse:28`,
`loop/plans:24`, `loop/directions:21`, `loop/route.ts` — because `requireOrgAccess` lets `public`
through by design, and none of them is also behind `selfHostGuard` the way the plans/directions lists
are. `needs-you` does neither.

**Exploit sketch.** An anonymous caller requests `?org=public` and receives
`{runner:false, plans:[], pausedRepos:[], runnerPaused:null}`. No tenant data crosses: the funnel org
has no `LoopPlan` or `LoopDrive` rows, and the read is org-scoped by construction
(`listLoopPlans(org)` / `listDriveRows(org)`). It is an inconsistency in a family whose other four
members state the rule, which is the shape that later becomes a real gap.

**Remedy.** Add `if (org === PUBLIC_ORG) return …403` beside the existing `!org` check. Not applied:
no boundary is crossed today, and the change is a 400/403 shift on a reachable endpoint.

### F5 — `informational` — `org/import` trusts the element type of `repos[]`

| | |
| --- | --- |
| Severity | informational |
| File | `src/app/api/org/import/route.ts:103`, `:264`–`:269` |

The body is typed `repos?: string[]` and `body.repos?.length` is the only check; a non-string element
reaches `parseForgeUrl(fn, …)` and `fn.includes("/")`.

**Exploit sketch.** `POST /api/org/import {org, repos:[1]}` throws inside the SSE `start()` callback,
so the caller gets a torn stream rather than the 400 the coordinate validator would have produced two
lines later. No tenant boundary is crossed — the coordinate validator (`isValidHandle` /
`isValidRepoName`) rejects every crafted *string*, the list is capped at `MAX_IMPORT_REPOS`, the org is
gated by `requireOrgAccess` + `requireFleetOrg`, and private-repo access still requires
`canMintInstallationToken`.

**Remedy.** `const repos = Array.isArray(body.repos) ? body.repos.filter((r): r is string => typeof r === "string") : []`,
matching the sibling filters in `org/loop/route.ts:247` and `org/skills/retire/route.ts:60`. Not
applied: robustness, not a security boundary, and this dispatch does not change product behaviour.

## Resolution (2026-10-06)

The operator answered the hardening ask — *"harden F1 and F3, keep the funnel"* — and four of the
five findings are now closed. Every test named below was confirmed to **fail with its fix line
removed**, so none of them is a matcher that has quietly stopped biting.

**F1 — closed on the four browser-only routes.** `requireSameOrigin` is now the first statement of
`org/skills/retire` POST, `org/ai-stance/apply-batch` POST, `org/segments/[id]/rule` **PUT and POST**,
and `org/local/probe` POST. Each route's `route.test.ts` pins a cross-origin 403 that reaches neither
the gate nor the store (five new cases — the rule route has one per verb).

The remaining two routes from the finding, `integrations/openai/sync` and `org/local/runner/merge`,
**stay open to scripts by operator decision**: a scheduler or a campaign driver sends no `Origin` and
no `Sec-Fetch-Site`, and adding the guard would 403 them. Each now carries a comment above its handler
saying so, naming this decision, so the next scan reads an intent rather than an omission. Their
weight is carried by what they do have: owner role on both, plus `selfHostGuard` on `runner/merge`.

One script did call a route that gained the guard: `scripts/arms.mjs` drives `org/local/probe`. It now
sends `origin: CFG.base` — by construction the origin it is posting to — so the headless arms driver
keeps working without the route having to stay open.

**F3 — closed.** `isValidAwsRegion` (the grammar `/^[a-z]{2}(-[a-z]+)+-\d$/`) and the single refusal
sentence `REGION_FORMAT_ERROR` live in the pure `src/lib/llm/bedrock-defaults.ts` and are re-exported
from `bedrock.ts`. `resolveBedrockRegion` now **throws** on a non-conforming *explicit* region rather
than handing it to the SDK, so the provider constructor and the test door inherit the refusal from the
one function that owns the precedence; the env fallbacks (`BEDROCK_REGION` → `AWS_REGION` → default)
keep their precedence and are deliberately unvalidated, being operator configuration.

Both caller-facing doors answer a clear **400 `Region must look like us-east-1.`**, never a 500:
`POST /api/org/llm-provider/test` checks `body.region` *and* a stored region (before the credential
lookup, so a malformed region costs no decrypt), and the save path `POST /api/org/llm-provider`
refuses one before it reaches the store — which is what keeps the read side from having to trust a
stored value. The accepted behaviour change stands: an org with a non-conforming saved region must
re-type it. Tests: `src/lib/llm/bedrock.test.ts` (valid shapes; `example.com/` and `us-east-1/../x`
refused; the env precedence; `testBedrockConnection` still answers `{ok:false,error}` rather than
throwing out of its contract) and a 400 case in each of the two route tests.
`src/lib/email/ses.ts` is unchanged — its comment now records *why* it carries no grammar: every
source on that path is env, and there is no request-supplied region to defend.

**F4 — closed.** `org/loop/needs-you` normalizes `?org=` with `trim().toLowerCase()` and 400s an empty
or `PUBLIC_ORG` value before `requireOrgAccess`, exactly as `loop/pulse:28` does. Test: `?org=public`,
`?org=Public` and `?org=%20public%20` are all refused and `listLoopPlans` / `listDriveRows` are never
called.

**F5 — closed.** `org/import` filters `repos[]` to strings with the sibling filter from
`org/skills/retire/route.ts:60`, before the stream opens. A list supplied with no string element at
all is a clean 400 rather than a fall-through to "list the whole org". Tests: `{repos:[1]}` → 400 with
no scan, and a mixed `["acme/web", 7, null]` imports the one real coordinate.

**F2 stays as documented, by operator decision** — the anonymous scan funnel keeps mailing a
caller-supplied address, because double opt-in changes the advertised no-signup flow. The trade-off
and its follow-up are already stated at the call site and in the finding above; nothing in
`src/app/api/scan/**` was touched by this pass.

## Method and limits

- Every non-test file in the scoped diff was opened. For heavily-modified files the whole handler was
  read; for small modifications the diff hunk was read in the context of the surrounding gate stack.
- A mechanical sweep of the diff for added lines combining a response/log with a credential word
  (`token|secret|key|credential|password|apiKey`) returned four hits, all of them refusal copy or the
  intended live-share mint. No secret reaches a response or a log on any changed path.
- What this scan does **not** cover, by scope: `src/features/**`, `src/components/**`, pages, the
  scoring engine, and the dependency tree. `SECURITY.md` places third-party dependency
  vulnerabilities, a self-supplied malicious `DATABASE_URL`/secret set, and single-instance
  rate-limit notes out of scope, and this report honours that.
- The structural guards that back several of the positive results are live and were not modified by
  this pass: `src/app/api/org/id-routes-gated.test.ts` (every `/api/org/[id]` route calls a gate, on
  comment-stripped source, with a seeded prose-only violation pinned) and
  `src/lib/db/wire-safe-dates.test.ts` (no client-crossing db type declares a `Date`).
